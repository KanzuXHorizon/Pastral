# Pastral name-clearance research

**Date:** 2026-08-03
**Status:** Provisional working name only
**Legal conclusion:** None. This document is product research, not a trademark opinion or legal clearance.

## 1. Search scope completed

Searches were performed for exact and near-exact uses of `Pastral` across:

- general web search;
- GitHub web index;
- Microsoft Apps/Store web index;
- crates.io and npm web indexes;
- software and clipboard-product queries;
- obvious domain/search-result usage;
- academic publication indexes surfaced through web search.

Queries included:

- `"Pastral" software`
- `"Pastral" app`
- `"Pastral" clipboard`
- `site:github.com Pastral`
- `site:apps.microsoft.com Pastral`
- `site:crates.io/crates pastral`
- `site:npmjs.com/package pastral`

## 2. Findings

### No prominent exact-name clipboard product found

The searches did not surface a prominent clipboard manager, Windows utility, GitHub repository, Microsoft Store listing, crates.io package, or npm package using the exact product name `Pastral`.

This is weak evidence only. Search indexes can omit unpublished, delisted, regional, private, newly registered, or unindexed uses.

### Existing academic use

`PASTRAL` is used as an acronym for an academic cybersecurity system:

> Privacy-aware AST and TRansformer-based Anomalous command-Line detection

Source:

- https://neurips.cc/virtual/2025/128606

Risk:

- The field is software/security-adjacent, although the product category differs from clipboard utilities.
- Search results and technical audiences may encounter ambiguity.
- This use prevents claiming the name is globally unique.

### Existing non-software uses

Search results show `Pastral` in music titles, user handles, product/color names, and transliteration/misspelling contexts. These uses reduce distinctiveness but do not by themselves establish a software trademark conflict.

### Package registries

No exact `pastral` package was surfaced in the public web indexes searched for crates.io or npm. This is not a reservation. Internal crate names must remain rebrandable and should not be published before the naming decision.

### Microsoft Store

No exact listing was surfaced through indexed web search. Microsoft Store availability must be checked directly in Partner Center and Store search across relevant markets immediately before reservation/submission.

### Domains and social handles

No domain or handle is treated as available based on search results. Availability changes continuously and must be checked and reserved only when the project owner authorizes registration and associated cost.

## 3. Trademark databases requiring formal review

Before public branding or commercial release, a qualified reviewer should perform exact, phonetic, visual, and related-goods searches in at least:

- USPTO Trademark Search: https://tmsearch.uspto.gov/
- EUIPO eSearch Plus: https://euipo.europa.eu/eSearch/
- WIPO Global Brand Database: https://branddb.wipo.int/
- TMview: https://www.tmdn.org/tmview/
- IP Vietnam trademark resources and professional local search.

Relevant goods/services should include software, downloadable computer programs, productivity utilities, data management, security/privacy software, and related SaaS even though Pastral is local-first.

## 4. Product recommendation

Continue using **Pastral** internally under these constraints:

1. Treat the name as provisional in UI, namespaces, binaries, package identity, and documentation.
2. Use replaceable internal prefixes such as `pastral_*` only behind centralized workspace/package metadata.
3. Do not publish packages, reserve Store identity, purchase domains, create public social accounts, or file trademarks without owner authorization.
4. Do not claim uniqueness or legal clearance.
5. Perform formal clearance before final logo production, signing identity, Store reservation, public beta, or marketing spend.

## 5. Rebranding safeguards

Architecture and repository requirements:

- centralize product display name and publisher identity;
- avoid embedding the brand in database table names and serialized domain types;
- version IPC independently from executable display names;
- use neutral application-data schema identifiers where practical;
- keep icon source files and wordmark separate;
- isolate package identity, URI schemes, named-pipe base name, registry keys, and app-data paths behind configuration/constants;
- include a tested data-path migration strategy before public beta.

## 6. Clearance gate

The name cannot move from `Provisional` to `Approved` until the release checklist contains evidence for:

- direct Store and package-registry checks;
- domain and social-handle decision;
- trademark searches in target markets and classes;
- review of confusingly similar names, not only exact matches;
- written owner acceptance of residual risk or legal counsel opinion;
- package identity and publisher-name reservation.
